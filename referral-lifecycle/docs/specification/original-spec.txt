1. Executive summary
Build SL Referrals & Rationale as a model-driven application over Dataverse. Each Opportunity represents one leaf Product. One Referral record represents one referral/approval cycle for that Opportunity and Product. It holds shared customer, broker, underwriting, transaction, risk, financial and document context. Each Referral Item is one Referral Reason applied to one Cover / Section and can be routed independently to an eligible Underwriting Authority assignment.
Retain Referral Decision as a separate user/team-owned table. This is not convenience duplication: more-information, onward-routing and revision scenarios produce multiple legally intelligible decision events. Records are created only by the Record Referral Decision Custom API, are immutable to normal users and preserve the authority evidence used at the time.
Safest POC baselineUse server-authoritative actions, immutable decisions and new-row revisions after rejection. Keep Authorised with Conditions and Partially Authorised - Completed configured but hide their commands by environment-variable feature flags until the product owner confirms them. Keep licence scheme/location, country and Cover / Section as metadata only in eligibility.

1.2 Non-negotiable design boundaries
No Case table as the primary Referral record; no generic polymorphic Referral Context table for the POC.
No Dataverse Quote table. Store external quote number/version/URL only.
No direct status patching from custom pages, JavaScript, imports or cloud flows.
No separate Authority Licence or User Authority Licence table until a document has its own lifecycle or is demonstrably shared.
No duplicated parent context on Referral Item; use lookups, quick views and reporting joins.
Only current/latest item revisions contribute to the aggregate parent status.

5.2 Rank-direction strategy
rankDirection = environment variable slr_RankDirectionif rankDirection == "HigherNumberGreater":    sufficient = assignmentRank >= requiredRank    onwardHigher = destinationRank > currentAssignmentRankelse if rankDirection == "LowerNumberGreater":    sufficient = assignmentRank <= requiredRank    onwardHigher = destinationRank < currentAssignmentRankelse:    throw CONFIG-RANK-001
Default: HigherNumberGreater because the seed numbering is ascending. This is an assumption, not a confirmed business rule. Do not submit any item while the variable is absent or invalid.

6.1 Duplication controls
Every snapshot name ends with Snapshot except standard Transaction Currency, which exists only to support Dataverse Money behavior.
Snapshots are written by plug-ins at submit/reassign/decision time, are on read-only form sections and are rejected in direct Update plug-ins.
Required/selected snapshots are refreshed only for the new current revision or an explicit reassignment; prior revisions/decisions never change.
Nightly reconciliation reports live-versus-assignment snapshot mismatch, but never rewrites Referral/Decision historical snapshots.
If reporting proves that a Decision-to-parent direct relationship is essential, add it only with a documented query/security benchmark and populate server-side; it is excluded now.

8.4 Exact live eligibility predicate
eligible(assignment, item, evaluationDateUtc) =    assignment.Product == item.Referral.Product    AND assignment.statecode == Active    AND assignment.statuscode == Current    AND assignment.EffectiveFrom <= evaluationDateUtc.Date    AND (assignment.EffectiveTo IS NULL OR assignment.EffectiveTo >= evaluationDateUtc.Date)    AND assignment.AuthorityLevel.statecode == Active    AND assignment.AuthorityLevel.CanApproveReferrals == true    AND assignment.AuthorityLevel.ComparisonRank IS NOT NULL    AND assignment.AuthorityRankSnapshot == assignment.AuthorityLevel.ComparisonRank    AND assignment.CanApproveReferralsSnapshot == assignment.AuthorityLevel.CanApproveReferrals    AND assignment.SnapshotIntegrity == Current    AND rankIsSufficient(assignment.AuthorityLevel.ComparisonRank, item.RequiredAuthorityLevel.ComparisonRank)    AND assignment.Underwriter.IsDisabled == false
Licence Scheme, Licence Location, Country of Referral and Cover / Section are intentionally absent from the predicate. They remain searchable metadata until the product owner confirms those dimensions. The selected assignment is revalidated at initial submission, review start, reassignment, onward routing and final decision. An assignment that expires between selection and submission/decision is rejected, not grandfathered.

10.1 Field behavior by group
Fields
Exact behavior
Referral; Referral Reason; Cover / Section
Parent cannot change after create. Reason/Cover editable only on current Draft or Revision in Progress. Server verifies active/effective reason and an active leaf Cover whose Product equals the parent Product.
Current Uniqueness Key
PreCreate/PreUpdate constructs lower-case parent GUID|reason GUID|cover GUID. Present only on the current row. The alternate key is the final concurrent duplicate guard.
Logical Item ID; Previous; Root; Revision; Is Current
Initial row gets a new logical GUID, Root=self and Revision 1. Start Revision copies logical/root, links Previous, increments revision and atomically moves the uniqueness key/current flag to the new row.
Summary/details/rationale/request
Required at submit for every reason; trimmed; reject whitespace-only input. Lock outside Draft, More Information response, or Revision in Progress contexts.
Detail Template Snapshot
Copy the reason template at submit so later reason changes do not alter how historical evidence is interpreted. A new revision gets a fresh snapshot at its submission.
Required level + rank snapshot
Required level is the underwriter-selected/derived current threshold. At submit, validate active/approving/rank and copy rank. The snapshot is historical; live level is still used for eligibility.
Selected assignment + approver + snapshots
Selection is a routing choice. Server validates all eligibility terms, derives approver and name/rank snapshots, grants access and prohibits client-supplied snapshot values.
Authority validation fields
Server writes a code, timestamp and safe message on every eligibility check. A failure leaves the lifecycle unchanged. The message must not reveal unrelated assignments.
Due/Sent/Review/Responded timestamps
Server clock only. Due On uses the configured SLA. Each is updated only by the corresponding API.
Information Cycle/Response
More Information increments the cycle. Underwriter may edit only the response; Resubmit requires nonblank response and clears it only on a later cycle if product policy allows.
Change Summary
Required on a new revision before submission. It explains the delta; it is never backfilled onto the rejected row.
Limit/pricing/duration/wording/exposure/risk/reinsurance/geography fields
Visibility and requiredness come from the immutable template snapshot. Validation is both client-assisted and server-enforced. Geography fields are never authority filters in POC.
Transaction Currency
Copy from parent only when Currency columns are present. Do not let users create a currency mismatch between shared and item money evidence.
Reminder fields
Asynchronous reminder flow updates operational counters only. These changes are excluded from lifecycle-trigger registrations to prevent loops.
Status / Owner
Only lifecycle APIs change status. Owner follows the parent owner team via controlled assignment; Assigned Approver access is separate.

10.2 Quick-create decision
Disable Quick Create. A valid item requires parent context, product-filtered Cover, reason-specific fields and server authority search. The Referral Builder is the only supported create/edit experience for ordinary underwriters; retain a fallback main form for administrators and support.

11.2 Parent-status decision points
Onward for Approval stays a parent status because the screenshot/meeting explicitly contains it. To prevent misrepresentation, set it only when all non-terminal current items are onward; otherwise keep Sent for Approval.
Authorised with Conditions is semantically distinct from recommendations: conditions are binding prerequisites while recommendations are advisory. Configure the value but default slr_EnableConditionalDecision=false until confirmed.
Partially Authorised - Completed is required only if the underwriter may accept a reduced scope without revising rejected items. Configure it but default slr_EnablePartialCompletion=false.
Revision in Progress means a new current child row linked to an immutable rejected predecessor. It never reactivates the rejected row.
Rejected - Underwriter Action Required is retained so a rejection does not silently close the business cycle before the underwriter accepts or revises it.

11.6 Deterministic parent aggregation
Recalculate(parentId, expectedParentRowVersion):  parent = retrieve parent with row version inside current transaction  items = retrieve Referral Items where Referral=parentId AND IsCurrentRevision=true  assert at most one current row for each LogicalItemId  if parent.ExplicitlyCancelled: return Cancelled / inactive  if items.empty OR parent.HasEverBeenSubmitted == false     OR every item is Draft: return Draft / active  if any item is MoreInformationRequired: return MoreInformationRequired / active  if any item is RevisionInProgress: return RevisionInProgress / active  if any item in {SentForApproval, InReview, Resubmitted, OnwardForApproval}:      if every nonterminal item is OnwardForApproval: return OnwardForApproval / active      return SentForApproval / active  terminalNonCancelled = items excluding Cancelled  if terminalNonCancelled.empty: throw SLR-AGG-ALLCANCELLED  if contains authorised-family AND contains Rejected:      return PartiallyAuthorised_UWActionRequired / active  if every terminalNonCancelled is Rejected:      return Rejected_UWActionRequired / active  if every terminalNonCancelled is authorised-family:      if any is AuthorisedWithConditions: return AuthorisedWithConditions / inactive      if any is AuthorisedWithRecommendations: return AuthorisedWithRecommendations / inactive      return Authorised / inactive  throw SLR-AGG-UNSUPPORTED
Precedence is mandatory: an information request must not be hidden by a rejected sibling; a new revision must not be reported as a completed mixed outcome; and any routed work keeps the parent active. Cancel is first because it is an explicit parent operation, not an inferred child outcome.

11.8 Race-condition controls
Execute each Custom API as a real-time main-operation plug-in; Dataverse rolls all organization-service writes back together when an exception is thrown.
Require ExpectedRowVersion and use IfRowVersionMatches/optimistic concurrency for the bound parent/item. Return SLR-CONCURRENCY-412 with a refresh instruction on mismatch.
Use unique Client Request ID keys for parent creation and decisions. A replay returns the prior result only when request identity/target/operation match; otherwise fail as token misuse.
The database alternate key on Current Uniqueness Key rejects simultaneous duplicate item creates. Catch duplicate-key faults and return SLR-DUP-409 without partial rows.
Retrieve current items and apply updates in stable GUID order; update aggregate counts/status last. Never call SharePoint, email or other network services in the transaction.

12.3 Concurrent duplicate-item algorithm
Client submits Reason and Cover IDs only; never accepts Current Uniqueness Key from the client.
PreValidation resolves parent Product and verifies Cover.Product, then constructs normalized parent|reason|cover GUID text.
PreOperation assigns the key and checks for a current match to return a friendly error early.
The active alternate key is the authoritative concurrent guard. If two requests race, one commits and the other receives duplicate-key SLR-DUP-409.
Start Revision runs in one transaction: create successor without current key, mark predecessor Is Current=false and clear its current key, then assign the key to successor and recalculate parent. Any failure rolls everything back.

17.2 Flow - Process Referral Notification
Setting
Exact construction
Type / run as
Scheduled cloud flow; Dataverse application user and shared-mailbox connection references.
Trigger
Recurrence every 1 minute. There is no trigger table/change/scope/select/filter/trigger condition; the Dataverse List rows action provides those settings.
List rows
Table Referral Notifications; Scope Organization; Select notification/event/referral/item/decision/recipient/email/template/payload/dedup/send-after/status/attempt/correlation; Filter rows: slr_processingstatus eq <PendingOption> and slr_sendafter le <Compose_Now>; Sort by slr_sendafter asc; Row count 50; pagination on.
Concurrency
Flow trigger concurrency On, Degree 1 so runs do not overlap. Apply to each Degree 1. Increase only after an atomic lease API is added/load-tested.
Actions
1 Compose Now=utcNow(). 2 List due Pending rows. For each: 3 Get row by ID. 4 Condition status still Pending and Send After<=Now. 5 Update Processing=Processing, Processing Started On=utcNow(), Attempt Count=add(coalesce(...),1). 6 Parse Payload JSON. 7 Switch Template Key/Event Type. 8 Compose record deep link. 9 Send an email from shared mailbox (V2). 10 Update Processing=Sent, Sent On=utcNow(), clear error/next attempt.
Expressions
Deep link: concat(variables('AppBaseUrl'),'&pagetype=entityrecord&etn=slr_referral&id=',outputs('Get_notification')?['body/_slr_referralid_value']). Current timestamp: utcNow().
Retry
Send action Settings > Retry Policy > Exponential, Count 4, Interval PT20S. Dataverse Get/Update use exponential Count 4. Do not retry invalid-recipient/business errors indefinitely.
Loop prevention
The trigger is recurrence, so row updates cannot retrigger it. The pre-send Get/Condition skips rows no longer Pending.
Failure scope
Place steps 5-10 in per-row Scope Try. Scope Catch runs after failed/timed out: update Processing=Failed, Last Error=substring(string(result('Try')),0,4000), Next Attempt On=addMinutes(utcNow(),15). Scope Finally logs run URL/correlation.
Dedup / logging
Producer alternate key prevents duplicate business intent. Processor never creates a second outbox row. Log flow run ID in trace notes or dedicated operational log only if governance approves.
Recovery
Failed Notification Monitor returns retryable rows to Pending and increments Retry Token. Admin may invoke Retry only after correcting address/config.
Tests
One submit email; same dedup event once; future Send After waits without blocking other due rows; invalid email to Failed; retry succeeds; existing Sent row is skipped.
